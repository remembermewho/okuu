# Фронтенд: журнал работы

Журнал частей I → M (фронтенд Окуу в `frontend/`). По каждой части: что сделано, решения,
файлы и сообщение для коммита. Решения, которые стоит проверить, собраны в разделе
«Решения на проверку» в конце.

Проверки после каждой части (в `frontend/`): `npm run typecheck`, `npm run lint`, `npm test`,
`npm run build`; если менялся бэкенд или `docs/openapi.yaml` — ещё `go test ./...` в `backend/`.

## Часть I. Каркас

### Что сделано
- Проект `frontend/`: Vite 7 + React 19 + TypeScript 5.9 (strict, `noUncheckedIndexedAccess`), React Router 7
  (data router), TanStack Query 5, react-hook-form 7 + zod 4, Radix Dialog / Dropdown Menu, lucide-react.
- Клиент API из `docs/openapi.yaml`: `npm run gen:api` (openapi-typescript → `src/api/schema.d.ts`),
  запросы — openapi-fetch (`src/api/client.ts`): `api.GET/POST…` + `unwrap()` → данные или `ApiError`
  {status, code, message, field, retryAfter}; ошибка сети — `code = 'network'`.
- Dev-proxy: `/api` и `/webhooks` → `http://localhost:8080` (адрес меняется `VITE_API_TARGET` — для e2e),
  приложение на `http://localhost:5173`.
- Роутинг: `/login`, `/register`, `/` (в единственный центр, к выбору центра или «нет центров»), `/centers`,
  `/c/:centerId/<раздел>`. Центр — в пути (как в API), роль — из `/me`. Разделы без доступа по роли —
  «Нет доступа». Разделы следующих частей пока — заглушки.
- Layout: шапка с названием центра и меню аккаунта (Radix Dropdown: сменить центр, выйти); нижнее меню
  на телефоне (owner/admin: Сегодня, Должники, Ученики, Ещё; teacher: Сегодня, Группы), на ≥ 1024px —
  боковое меню и контент до 1100px. Страница «Ещё» — остальные разделы и выход.
- Базовые компоненты (`src/components/ui`): Button / ButtonLink / ButtonAnchor, Input, Select, Textarea,
  Checkbox, Card, Badge, Dialog (Radix; на телефоне шторка снизу), ConfirmDialog, Toast (свой, aria-live),
  Skeleton / SkeletonList, EmptyState, ErrorState, FormError, MoneyText, PageHeader.
- S1: вход, регистрация центра, выход; защищённые маршруты (без сессии — на вход с `?next=`; возврат только
  на свои пути — без открытого редиректа).
- Ошибки: `errorMessage()` — понятный текст по `code` (все коды из docs/errors.md в `ru.errors.codes`;
  у `validation` — сообщение сервера); `applyFieldError()` — `field` под поле формы; 401 с любого запроса —
  на вход; нет сети — тост «Повторить» (перезапрос); ошибки мутаций — тостом, если форма не показала сама.
- Утилиты: `utils/money.ts` (тыйыны ↔ сомы, «34 500 с», ввод «1 500,50»), `utils/date.ts`
  («19 октября», «19.10.2026», арифметика дат без сдвига поясом), `utils/phone.ts` (как `NormalizePhone` бэкенда).
- Тесты (Vitest + Testing Library, мок `fetch`): money, date, phone; вход (ошибки полей, `invalid_credentials`,
  429 с минутами из `Retry-After`, `next`, чужой `next`), регистрация (`field` с сервера, `phone_taken`,
  короткий пароль без запроса), защищённые маршруты, меню преподавателя, «нет доступа», выход.
- Инфраструктура e2e (заранее, для просмотра экранов): `e2e/start-backend.mjs` — чистая база `okuu_e2e`
  в контейнере `okuu-db`, свежий бинарник, сервер на :8091 с `APP_ORIGIN=http://localhost:5174`, Telegram выключен;
  `playwright.config.ts` — бэкенд :8091 + Vite :5174, проекты 390px и 1280px.
- `.gitignore` (node_modules, dist, отчёты Playwright, `.env*.local`), раздел «Frontend» в CLAUDE.md.

### Решения
- **CSS Modules + CSS-переменные, не Tailwind.** Токены дизайна — одним списком в `src/styles/global.css`
  (`--primary`, `--debt` …), стили компонентов — рядом с ними. Без сборочного плагина и конфигурации
  утилит, разметка без длинных цепочек классов; для небольшого набора экранов этого достаточно.
- **Шрифт Golos Text — пакетом `@fontsource/golos-text`** (те же файлы Google Fonts, но со своего домена):
  не нужно разрешать в CSP `fonts.googleapis.com`/`fonts.gstatic.com` (в Caddyfile `font-src 'self'`),
  нет запроса к Google при каждом открытии, шрифт есть и офлайн.
- **Версии библиотек — проверенные мажоры, а не самые новые:** на сегодня вышли TypeScript 7, Vite 8,
  Vitest 5, React Router 8, ESLint 10, `@hookform/resolvers` 6, но у них конфликты peer-зависимостей
  (eslint-plugin-react не поддерживает ESLint 10, resolvers 6 тянет effect 4). Взяты TS 5.9, Vite 7,
  Vitest 3, React Router 7, ESLint 9, resolvers 5 — совместимы между собой.
- **`docs/openapi.yaml`: убран заголовок `Origin` из параметров операций** (это правка документа бэкенда,
  не кода). Он был описан как обязательный параметр, и сгенерированный клиент требовал передавать его в
  каждом изменяющем запросе, хотя из JS его задать нельзя — его ставит браузер. Требование `Origin`
  осталось в описании API (раздел CSRF) и в ответах `403 bad_origin`. `go test ./...` зелёный (сверка
  спецификации с роутером и валидация ответов проходят).
- **Тексты только в `src/i18n/ru.ts`** — правило ESLint `react/jsx-no-literals` (строка в JSX — ошибка).
- **Центр — в пути `/c/:centerId`**, как в API: ссылку на экран можно переслать, обновление страницы
  не теряет центр. Первый экран: owner/admin — «Должники», teacher — «Сегодня».
- **Базовый адрес API — `window.location.origin`** (тот же домен): абсолютный адрес нужен, чтобы
  `Request` собирался и в тестах.
- **ESLint строгий:** `--max-warnings 0`; правило `react-refresh/only-export-components` выключено
  (хуки рядом с компонентами — осознанно, влияет только на HMR).
- Тестовая обвязка: React Router передаёт в `Request` `AbortSignal` из jsdom, а `Request` Node его
  не принимает — в `src/test/setup.ts` `Request` в тестах не получает `signal`.

## Часть J. Должники, ученики, карточка ученика

### Что сделано
- **S2 Должники** (`/c/:id/debtors`): итоги месяца (собрано / начислено, долг и число должников, «ожидают
  оплаты» — срок ещё не наступил), фильтр по группе, список с суммой долга, днями просрочки, группами и
  статусом Telegram родителя. «Напомнить» в строке и «Напомнить всем» (с подтверждением); итог — окно
  «Отправлено N сообщений» и список, кому не отправлено и почему (`skipped[].reason` → текст).
- **S4 Ученики** (`/c/:id/students`): поиск по ФИО / телефону (с задержкой 300 мс), фильтры статус / группа /
  Telegram, подгрузка по `next_cursor` («Показать ещё»), пустые состояния («пока нет» со ссылкой на импорт /
  «никого не нашли»). Фильтры — в адресе (`?q=&status=&group=&tg=`): обновление и «назад» их не теряют.
- **«Добавить ученика»**: ФИО, дата рождения, родитель (имя, телефон), скидка (нет / фиксированная в сомах /
  процент), запись в группу (группа, тариф — по умолчанию тариф группы, дата начала, «за текущий месяц»:
  полностью / вручную / не начислять — только для месячного тарифа; для абонемента — подсказка, что
  начислится). Ошибки сервера с `field` — под полями. После создания — переход в карточку.
- **S5 Карточка ученика** (`/c/:id/students/:studentId`):
  - баланс (долг — оранжевым, аванс, «долгов нет»), скидка, большая кнопка «Отметить оплату»;
  - родитель: имя, телефон (`tel:`), статус Telegram, последнее напоминание; «Напомнить о долге» (если долг и
    Telegram подключён; если не отправлено — тост с причиной); «Пригласить в Telegram» → окно со ссылкой на
    бота, «Скопировать ссылку», «Отправить в WhatsApp», текст приглашения ru/ky и «Скопировать текст»;
  - группы: тариф, цена, даты, «начислено по …», остаток абонемента (≤ 1 — оранжевым), «Завершить» (с датой),
    «Продлить абонемент» (для абонемента), «Записать в группу»;
  - история операций (по 20, «Показать ещё»): вид, способ, дата, период, срок, комментарий, сумма со знаком;
    отменённые — зачёркнуто с причиной; «Отменить» → окно с обязательной причиной (от 3 символов);
  - посещения по месяцам (← →): итог «был / не был / уважительная», список отметок, «списано с абонемента»;
  - «Ещё действия»: возврат, поправка, пауза / вернуть в учащиеся / «ученик ушёл» (с подтверждением).
- **Оплата / возврат / поправка** — одно окно. Idempotency-Key создаётся при открытии формы и живёт до
  закрытия: повтор после ошибки или двойное нажатие не создадут вторую операцию; новое открытие — новый ключ.
- Тесты (+15): должники (итоги и просрочка, фильтр группы в запросе, «напомнить всем» с итогом и причинами,
  «напомнить» по строке, пустой список); карточка (долг / родитель / история, Idempotency-Key — тот же при
  повторе и новый при новом открытии, поправка «к долгу» → отрицательная сумма и обязательная причина, отмена
  только с причиной, Finik-оплату админ отменить не может, приглашение со ссылкой и WhatsApp, напоминание с
  причиной, учителю — «нет доступа»); добавление ученика (создание + запись с `first_month`, ошибка поля с сервера).
  Общие тестовые данные — `src/test/fixtures.ts`.
- Проверено вручную на настоящем бэкенде (временный `e2e/peek.spec.ts`, 390px и 1280px): добавление ученика
  с записью в группу → карточка с начислением → окно оплаты → приглашение → должники → список.

### Решения
- **Ученик и запись в группу — два запроса** (`POST /students`, затем `POST /students/{id}/enrollments`):
  в API нет создания ученика сразу с записью. Если запись не удалась, ученик остаётся, показывается тост
  «Ученик добавлен, но записать в группу не получилось: …», и открывается его карточка — там можно записать.
- **Сумма оплаты подставляется равной долгу** (в целых сомах) — самый частый случай; её можно изменить.
- **Поправка** — переключатель «Добавить к долгу / Уменьшить долг» и сумма без знака (знак ставит форма),
  причина обязательна. Так не нужно объяснять администратору знак минус.
- **«Отменить» есть и у начислений** (R15 позволяет отменять любую операцию). Оплату Finik отменяет только
  владелец — у администратора кнопки нет (сервер тоже это проверяет).
- **В карточке «Долг» — любой отрицательный баланс**, в том числе когда срок оплаты ещё не наступил; в списке
  должников такой ученик — в «Ожидают оплаты». Баланс в API не знает о сроке, а разделять «долг / к оплате» в
  карточке по истории операций — лишняя логика на клиенте.
- **«Напомнить о долге» в карточке** показывается только при долге и подключённом Telegram — иначе сервер всё
  равно пропустит ученика (`no_telegram` / `no_debt`).
- **Телефон родителя нормализуется перед отправкой** (`0700 111 222` → `+996700111222`), как на бэкенде.
- **Фильтры списка учеников — в адресной строке**, а не в состоянии компонента.

### Неудобства API (не правил)
- Нет создания ученика вместе с записью в группу одним запросом — при сбое второго запроса ученик остаётся
  без группы (обработано, см. выше).

## Часть K. Сегодня, группы, тарифы, сотрудники, приглашение

### Что сделано
- **S3 Сегодня** (`/c/:id/today`): день с ← → и выбором даты в разрешённом окне (как на бэкенде: преподаватель —
  сегодня−7…сегодня, владелец и админ — до сегодня+30, назад без ограничения); дата — в адресе (`?date=`), дата вне
  окна сводится к краю. Занятия дня карточками: время, группа, «внеплановое», «Отмечено N из M»; у каждого ученика
  крупные кнопки «Был / Не был / Уважит.» (48px, цвета: зелёный / оранжевый / синий); «Все были» (отмечает только
  неотмеченных) и «Сохранить» — уходят только изменённые отметки; повторное нажатие снимает отметку (`status: null`);
  несохранённые изменения подсвечены точкой и счётчиком, при смене дня — подтверждение. Владелец/админ: долг у
  ученика (`has_debt`), остаток абонемента (≤ 1 — оранжевым), ссылка на карточку, меню занятия «Отменить / Вернуть»,
  «Внеплановое занятие» (группа + время; `lesson_exists` — под временем).
- **S6 Группы** (`/c/:id/groups`): карточки — расписание одной строкой («Пн, Ср 15:00–16:30»), преподаватель,
  число учеников, тариф; «Показать архив»; создание / изменение (название, преподаватель из сотрудников, дни
  недели кнопками + время начала и конца для каждого дня, тариф по умолчанию); «В архив» с подтверждением.
  Состав группы (`/c/:id/groups/:groupId`, владелец и админ): ученики с балансом, ссылки на карточки.
  Преподаватель видит только список своих групп, без изменений.
- **Тарифы** (`/c/:id/tariffs`): список (тип, «за N занятий», цена), архив, создание и изменение (название,
  «В месяц / Абонемент», цена в сомах, число занятий для абонемента), «В архив». `tariff_in_use` — в форме.
- **Сотрудники** (`/c/:id/staff`): список (имя, телефон, роль, «вы»). Владелец: «Пригласить» (роль с пояснением,
  имя) → ссылка, «Скопировать ссылку», «Отправить в WhatsApp»; меню сотрудника — сменить роль, удалить из центра
  (с подтверждением; `teacher_has_groups` / `owner_protected` — тостом); действующие приглашения с «Отозвать».
  Админ видит список без управления.
- **Приглашение** `/invite/:token` (без меню и без входа): центр, роль, для кого, срок. Вошедший — «Принять
  приглашение» и переход в новый центр (или «Это не вы? Выйти»); новый — имя (подставлено из приглашения),
  телефон, пароль; `login_required` → «Войти и принять» (`/login?next=/invite/…`); недействительная ссылка — экран
  «Приглашение недействительно».
- Порядок меню — как в ТЗ: Должники · Сегодня · Ученики · Ещё.
- Тесты (+24): окно дат; отметки (в запросе только изменения, снятие повторным нажатием, «Все были», счётчик),
  край окна для преподавателя, подтверждение при смене дня, админ: долг, отмена занятия, внеплановое с
  `lesson_exists`; расписание одной строкой и его проверка; группы (список, создание с днями и временем, ошибки
  времени и сервера, вид преподавателя, состав, архив); тарифы (список, абонемент, `tariff_in_use`); сотрудники
  (приглашение и WhatsApp, смена роли, `teacher_has_groups`, админ без управления); страница приглашения
  (недействительная, регистрация, `login_required`, вошедший).
- Проверено на настоящем бэкенде (390 и 1280px): тариф → группа на сегодняшний день недели → три ученика → отметки
  и сохранение → приглашение → регистрация по ссылке во втором браузере → «Сегодня» преподавателя.

### Решения
- **Повторное нажатие на выбранную отметку снимает её** — так исправляют случайное нажатие (API принимает
  `status: null`). Кнопка «Все были» — не из ТЗ, но экономит нажатия: обычно отсутствующих меньше.
- **Сохранение — по занятию**, отправляются только изменённые отметки. Несохранённые отметки при смене дня —
  подтверждение «Перейти без сохранения».
- **«Сегодня» — по часам браузера.** Бэкенд считает «сегодня» в поясе центра; если они разойдутся (около
  полуночи, другой пояс), сервер ответит ошибкой даты, и она будет показана. Пояс центра преподаватель
  прочитать не может (`/settings` — владелец и админ).
- **Состав группы — через список учеников с фильтром `group`** (отдельного эндпоинта нет); доступен владельцу и
  админу, преподавателю — нет (список учеников ему запрещён API).
- **Расписание — кнопки дней недели**, у каждого дня своё время; новый день берёт время предыдущего.
  Несколько занятий в один день API допускает — форма их сохраняет, но добавить второе время в тот же день
  из формы нельзя (редкий случай; можно добавить внеплановое занятие).
- **Преподаватель группы — любой сотрудник** (бэкенд проверяет только членство), в списке подписана роль.
- **Тарифы можно изменять** (в API есть PATCH), не только создавать и архивировать.
- **После принятия приглашения** центр находится сравнением списка центров до и после (в `PublicInvite` нет id
  центра).
- **Порядок меню — как в ТЗ** («Долги · Сегодня · Ученики · Ещё»), в части I «Сегодня» стояло первым.

### Неудобства API (не правил)

- Нет «сегодня» центра для преподавателя — окно дат считается по часам браузера.

### Решения
- **«За текущий месяц» в импорте — только «Начислить по тарифу» и «Не начислять».** В `openapi.yaml`
  `first_month` у импорта перечисляет и `manual`, но бэкенд принимает только `full` / `none` (ручной суммы
  в запросе нет). Бэкенд не трогал — записано в «Неудобства API».
- **QR-код на странице оплаты не рисуется.** Для этого нужна библиотека генерации QR; онлайн-оплата Finik ещё не
  подключена (а Finik по CLAUDE.md пока не трогаем), кнопка «Оплатить онлайн» ведёт на `pay_url` банка.
- **Настройки открыты только владельцу** (как в ТЗ, S8). API даёт читать и админу, но меню ему не показываем.
  Форма умеет режим «только чтение» на случай, если раздел откроют и админу.
- **Часовой пояс — список** (Бишкек, Алматы, Ташкент, Душанбе, Москва + текущий, если другой), а не ввод IANA-имени.
- **В форме настроек поле «День начисления» показывает новый день**, если смена уже ждёт следующего месяца, —
  плашка рядом объясняет, с какой даты.
- **Журнал: «Было / Стало» — как JSON.** Человекочитаемый разбор полей для каждого действия — большая работа;
  JSON честно показывает изменение.
- **Цвет ошибок импорта — `--danger` (#A3261B на #FBE7E5, контраст ≈ 6:1)**: добавлен токен `--danger-light`.
  Предупреждения — цвет долга (оранжевый).
- Уход на сайт банка — `utils/redirect.ts` (отдельная функция, чтобы подменять в тестах).

### Решения
- **Ссылка оплаты для e2e — прямой `INSERT` в `okuu_e2e`** (hex(sha256) токена, как делает бэкенд). Получить её
  можно только кнопкой «Оплатить» в боте, а реальный Telegram в тестах не участвует. Код бэкенда не менял.
- **Должник в e2e детерминирован:** срок оплаты 0 дней, запись с 1-го числа → долг просрочен с 2-го числа.
  1-го числа месяца сценарий `money` пропускается (`test.skip`) — долг ещё не просрочен.
- **Деньги и сотрудники в e2e — через интерфейс**, данные для импорта / оплаты / доступности — через API
  (быстрее, и это подготовка, а не проверяемый путь).
- **E2E не в CI** — требуют Docker с Postgres и сборку бэкенда; при желании можно добавить отдельной задачей
  по образцу `backend` (сервис postgres + `E2E_PG_CONTAINER`).
- **Разделение на чанки (`manualChunks`) вместо ленивых маршрутов:** проще и не меняет поведение экранов
  (без мигания загрузки при переходах); приложение после gzip ≈ 230 кБ.
- **Sourcemaps в сборке оставлены** (`build.sourcemap: true` из части I) — удобно разбирать ошибки; исходники
  фронтенда не секретны. Если не нужно — `sourcemap: 'hidden'`.

## Решения на проверку

1. `docs/openapi.yaml`: `Origin` убран из параметров операций (часть I) — иначе сгенерированный клиент
   требует передавать заголовок, который ставит браузер.
2. Шрифт — пакет `@fontsource/golos-text`, а не подключение с fonts.googleapis.com (CSP, приватность).
3. Версии библиотек на мажор ниже самых новых (совместимость, см. часть I).
4. Добавление ученика с группой — два запроса; при сбое записи ученик остаётся без группы (часть J).
5. В карточке ученика «Долг» — любой отрицательный баланс, даже до срока оплаты (часть J).
6. Сумма в окне оплаты по умолчанию = долг, в целых сомах (часть J).
7. «Сегодня»: повторное нажатие снимает отметку; кнопка «Все были» (не из ТЗ) (часть K).
8. «Сегодня» считается по часам браузера, а не по поясу центра (часть K).
9. Порядок меню изменён на ТЗ-шный: Должники · Сегодня · Ученики · Ещё (часть K).
10. Тарифы можно изменять, не только создавать и архивировать (часть K).
11. Импорт: «За текущий месяц» — только full / none; в openapi.yaml есть `manual`, бэкенд его не принимает (часть L).
12. Страница оплаты без QR-кода — только кнопка «Оплатить онлайн» (часть L).
13. Журнал: «Было / Стало» показывается как JSON (часть L).
14. Часовой пояс в настройках — выбор из короткого списка (часть L).
15. E2E: ссылка оплаты вставляется прямо в базу `okuu_e2e` (её выдаёт только бот) (часть M).
16. E2E не добавлены в CI — только локально (часть M).
17. Сборка делится на чанки (`manualChunks`), а не ленивые маршруты; sourcemaps в сборке оставлены (часть M).
18. Сборка фронтенда на сервере — в контейнере `node:22-alpine`, Caddy монтирует `frontend/dist` (часть M).
